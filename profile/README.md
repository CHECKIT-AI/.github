# CheckIt
### 계약 전, 놓친 조항까지 한 번 더 체크

CheckIt은 계약서를 작성하거나 검토할 때 주요 조항을 확인하고,
누락된 내용이나 사용자에게 불리할 수 있는 조항을 살펴볼 수 있도록 돕는 서비스입니다.

복잡한 계약 내용을 이해하고, 계약 체결 전에 확인할 사항을 파악할 수 있도록 지원합니다.

> CheckIt의 검토 결과는 참고용 정보이며, 전문적인 법률 자문을 대체하지 않습니다.

## 프로젝트 소개

계약서를 검토할 때는 어떤 조항이 필요한지,
어떤 내용이 자신에게 불리할 수 있는지 판단하기 어려울 수 있습니다.

CheckIt은 이러한 어려움을 줄이기 위해 다음과 같은 검토를 지원하는 것을 목표로 합니다.

- 계약서에 필요한 주요 조항이 포함되어 있는지 확인
- 사용자에게 불리할 수 있는 조항 식별
- 의미가 모호하거나 추가 확인이 필요한 내용 안내
- 검토 결과를 바탕으로 계약 전 확인할 사항 정리

## 주요 기능

> 아래 기능은 기획 기준이며, 개발 과정에서 변경될 수 있습니다.

| 기능 | 설명 |
| --- | --- |
| 계약서 내용 검토 | 계약서에 포함된 조항을 분석합니다. |
| 누락 조항 확인 | 계약 유형에 따라 확인이 필요한 주요 조항의 누락 가능성을 안내합니다. |
| 불리한 조항 확인 | 사용자에게 불리하게 작용할 가능성이 있는 내용을 안내합니다. |
| 검토 결과 제공 | 주의가 필요한 내용과 추가 확인 사항을 정리해 제공합니다. |

## 이용 흐름

1. 검토할 계약서 내용을 입력합니다.
2. CheckIt이 계약서의 조항을 분석합니다.
3. 누락 가능성이 있는 조항과 주의가 필요한 내용을 확인합니다.
4. 검토 결과를 참고하여 계약서를 수정하거나 전문가에게 추가 검토를 요청합니다.

## 브랜치 운영 규칙

| 브랜치 | 용도 |
| --- | --- |
| `main` | 배포용 브랜치 |
| `develop` | 개발 내용 통합 브랜치 |
| `feat/#이슈번호` | 이슈별 기능 개발 브랜치 |

### 개발 진행 방법

1. 작업할 이슈를 생성하고 담당자를 지정합니다.
2. 최신 `develop`에서 `feat/#이슈번호` 브랜치를 생성합니다.
3. 작업 내용을 커밋하고 원격 브랜치에 push합니다.
4. `develop`을 대상으로 Pull Request를 생성합니다.
5. 코드 리뷰 후 `develop`에 병합합니다.
6. 배포 시 `develop`의 변경사항을 Pull Request로 `main`에 반영합니다.

`main`과 `develop`에 직접 push하지 않고 Pull Request로 병합합니다.

### 브랜치 생성 예시

이슈 번호가 `12`인 경우:

```bash
git switch develop
git pull origin develop
git switch -c 'feat/#12'
git push -u origin 'feat/#12'
```

### Pull Request 작성 규칙

- 제목에 작업 내용이 드러나도록 작성합니다.
- 관련 이슈를 연결합니다.
- 주요 변경사항과 테스트 결과를 작성합니다.
- 화면이 변경된 경우 스크린샷을 첨부합니다.
- 리뷰에서 요청된 내용을 반영한 후 병합합니다.
